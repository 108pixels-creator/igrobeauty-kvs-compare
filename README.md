# IGRObeauty – стили на страницах сайта

Статичный сайт-просмотрщик: 7 стилей дизайна IGRObeauty на трёх страницах сайта
(«Бренды-партнёры», «Сотрудничество», «О компании») в десктопной ширине 1440 px
и ключевые визуалы (KV) стилей.

Страница – это полный снимок макета. Её листают как настоящий сайт, а стиль
переключают мгновенно: место на странице сохраняется. Панель внизу экрана можно
скрыть, тогда на экране только сайт.

Без внешних зависимостей и запросов: работает с диска (двойной щелчок по
`index.html`) и на GitHub Pages.

## Как смотреть

| Клавиша | Что делает |
|---|---|
| `1`–`7` | стиль |
| `←` / `→` | предыдущий / следующий стиль |
| `Q` `W` `E` или `Shift+1` `2` `3` | страница |
| `K` | ключевой визуал стиля (открыть / закрыть) |
| `Esc` | закрыть KV или подсказку |
| `H` | скрыть / показать панель |
| `?` | подсказка |

Клавиши работают и в русской раскладке.

**Загрузка.** Открытая страница грузится первой. Соседние стили заранее скачиваются и раскодируются,
поэтому `←` / `→` переключают мгновенно. Через пару секунд в фоне по одной докачиваются все остальные
картинки и KV: сначала эта страница в других стилях, потом KV и другие страницы этого стиля, потом остальное.
Пока грузится открытое, фон ждёт. В режиме экономии трафика фоновой подгрузки нет.

Состояние хранится в адресе, поэтому ссылкой можно открыть нужный вид:

- `index.html#cooperation/kv3` – «Сотрудничество» в стиле KV-3;
- `index.html#about/kv5/kv` – KV стиля KV-5 (на фоне – «О компании»);
- без хвоста открывается `#cooperation/base`.

**Локально.** Двойной щелчок по `serve-local.cmd`: он запускает сервер на http://127.0.0.1:8791/ и открывает браузер. Сервер работает, пока открыто его чёрное окно, и не зависит от приложения Claude: его серверы приложение гасит, когда сессия простаивает. Файл в публикацию не входит (`.gitignore`).

## Что где лежит

```
index.html        разметка
style.css         оформление панели и экранов
app.js            логика просмотрщика
data.js           стили, страницы, пути к KV – правится руками
assets/pages/     снимки страниц: <page>-<style>.webp
assets/kv/        ключевые визуалы: base.webp, kv1.webp … kv5.webp, kv2l.webp
_work/            рабочие PNG из Figma (для сайта не нужны)
.nojekyll         чтобы GitHub Pages отдавал файлы как есть
```

Ключи (латиница, строчные):

- страницы – `brands`, `cooperation`, `about`;
- стили – `base`, `kv1`, `kv2`, `kv3`, `kv4`, `kv5`, `kv2l`.

## Как обновить снимки страниц

1. Снять страницу целиком шириной 1440 px. Файл может быть 1× (1440 px)
   или 2× (2880 px, чётче на Retina). Просмотрщик всегда показывает его на 1440 px.
2. Сохранить в WebP и назвать `<page>-<style>.webp`, например `cooperation-kv3.webp`.
3. Положить в `assets/pages/` с заменой старого файла.
4. По желанию поправить высоту в `data.js` (`heights`). Она нужна только для подсказки
   на панели: просмотрщик берёт размер из самого файла.

Важно:

- WebP не бывает больше 16 383 px по любой стороне. Значит, в 2× страница может быть
  не выше 8 191 px (в 1440). Более длинную страницу сохранить в 1× или 1,5×.
- GitHub Pages различает регистр букв: `Cooperation-KV3.webp` не найдётся.
- Если снимка нет, на его месте серая заглушка «Снимок cooperation/kv3 ещё не загружен»
  с путём к файлу. Остальное работает.
- После замены картинок на GitHub Pages браузер может ещё до 10 минут показывать старые.
  Чтобы обновились сразу, впишите в `data.js` новое значение `version`, например
  `version: '2026-11-17'`.

## Как добавить или заменить KV

1. Положить файл в `assets/kv/`, например `assets/kv/kv2l.webp`.
   Достаточно 2000–3000 px по длинной стороне.
2. В `data.js` у нужного стиля вписать путь: `kv: 'assets/kv/kv2l.webp'`.

Пока у стиля `kv: null`, на экране KV заглушка «Ключевой визуал для этого стиля
появится позже». С 17.11 KV есть у всех семи стилей.

## Как поменять стили или страницы

Всё в `data.js`:

- порядок в `styles` – это номера кнопок и клавиш (до 9 стилей);
- `name` – полное название (подсказка и подпись на панели);
- `short` – короткая надпись на кнопке (видна на экранах шире 1860 px, на узких
  только номера);
- первые три страницы в `pages` получают клавиши `Q`, `W`, `E`.

## Публикация на GitHub Pages

Репозиторий: https://github.com/108pixels-creator/igrobeauty-kvs-compare (ветка `main`).
Адрес после включения Pages: https://108pixels-creator.github.io/igrobeauty-kvs-compare/

Обновить снимки и выложить: `python -I _work/export_all.py <версия>` (WebP, высоты, `version`),
затем `git add -A`, `git commit`, `git push`. `MANIFEST.md`, `_work/` и `serve-local.cmd` в репозиторий не идут.

Как это было настроено с нуля:

1. Создать на GitHub репозиторий, например `igrobeauty-style-showcase`.
   На бесплатном аккаунте Pages работает только у публичных репозиториев.
2. Залить содержимое этой папки в корень ветки `main`, чтобы `index.html` оказался
   в корне репозитория:

   ```
   cd D:\igrobeauty\igro-design-pages\style-showcase
   git init -b main
   git add .
   git commit -m "Style showcase"
   git remote add origin https://github.com/<аккаунт>/igrobeauty-style-showcase.git
   git push -u origin main
   ```

   Папка `_work` (исходные PNG) не публикуется: она уже указана в `.gitignore`.
3. На GitHub: Settings → Pages → Build and deployment → Source: **Deploy from a branch**
   → Branch: **main**, папка **/ (root)** → Save.
4. Через 1–2 минуты сайт откроется по адресу
   `https://<аккаунт>.github.io/igrobeauty-style-showcase/`.
   Ссылка на конкретный вид – с хвостом, например `…/igrobeauty-style-showcase/#cooperation/kv3`.

Дальше обновление – обычный `git add`, `git commit`, `git push`: Pages пересоберётся сам.

Ограничения GitHub: файл – до 100 МБ, сайт – до 1 ГБ. Страница закрыта от поисковиков
(`noindex`), но открывается у всех, у кого есть ссылка.
